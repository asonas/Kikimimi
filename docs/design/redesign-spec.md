### 1.5 角丸と線

- ウィンドウ 14、ダイアログ・メニューバーカード 12、パネル / 入力欄 / ボタン / メーター / Notice 8。ボタンの角丸は SDS 変数 radius-200 = 8。
- スイッチ 40 x 24 の全角丸 (pill)。メーターのセグメントと進捗バーに角丸は無い。
- 線は 1px。ウィンドウとダイアログの外枠は line (#d6d3d1)。Divider は高さ 1 の line。入力欄と secondary ボタンの枠は control (#78716c)。
- 影 (drop shadow) の定義は確認した 3 フレーム (01, ダイアログ 2 種) には無い。

### 1.6 ボタン

全て 高さ 40 (padding 縦 9 + 文字 22 + 縦 9)、横 padding 16、文字は label (14/22 Medium)、角丸 8。最小の幅は 80 前後 (テキストボタン「設定」「開く」「変更」は幅 80 固定)。操作は 40pt 以上というルールと一致する。

| 種類 | 背景 | 枠 | 文字 | 使用例 |
| --- | --- | --- | --- | --- |
| Primary (濃) | ink #1c1917 | 無し | surface (白) | 「新しい録音」「録音を開始」「ノートを書き出す」「要約を作成」 |
| Secondary (枠付き) | surface #ffffff | 1px control #78716c | ink | 「録音を準備」「キャンセル」「Finderで表示」「Markdownをコピー」 |

| Text (枠なし) | 無し | 無し | ink | 「設定」「録音一覧」「開く」「変更」「録音の情報」「閉じる」 |

ホバー: プロトタイプ上、Primary / Secondary / Text のホバーは Figma の共通 Button コンポーネント (Simple Design System) の variant に差し替える設定になっている。Primary ホバーの塗りは #1e1e1e、Neutral ホバーは #cdcdcd、Subtle ホバーは塗り無し + 1px #d9d9d9 枠。これらの色は Kikimimi のトークンではなく共通テンプレート由来で、Kikimimi 色との整合は未検討に見える (曖昧)。無効 (disabled)・フォーカスの Kikimimi 版デザインは無い。

### 1.7 最小ヒットサイズ

- 「操作は40pt以上」。ボタンは 高さ 40。toolbar の戻る chevron アイコンは 40 x 40 のインスタンス。設定の歯車は 20 x 20 のアイコン + 80 x 40 のテキストボタン。
- 録音一覧の各行は行全体がクリック対象 (高さ約 88)。
- スイッチは見た目が 40 x 24 で 40 未満。ただし Switch Field の最小幅は 120 (左に状態文字「表示する / 表示しない」を伴う)。クリック領域が文字を含むかは未指定 (曖昧)。

### 1.8 オーディオメーター部品 (Kikimimi / Audio meter、component 5:179)

構造 (縦積み、間隔 8):
- コンテナ: 背景 ink #1c1917、padding 縦 20 / 横 24、角丸 8。幅は配置先で変わる (Foundations 760、録音準備カード 444、録音中 992、設定プレビュー 792)。高さは内容で決まり約 116。
- Channel label 行 (横並び、間隔 12): 左 = チャンネル名 (label 14/22 Medium、白)、右 = 現在値の文字 (label、白、例「−18 dBFS」)。
- Meter rail: 高さ 18、セグメント 30 個を等幅 (flex) で並べ、セグメント間隔 3。セグメントに角丸・枠無し。
  - 点灯: meterGreen #69c38b。琥珀域: meterAmber #efbe60。未点灯: meterOff #454b46。
  - ピークホールドの目印: 該当セグメント (通常は未点灯側) の右端に 2px の白 (surface) 縦線。
- dBFS scale 行 (横並び space-between): 「−60」「−48」「−36」「−24」「−12」「0」(small 13/20、白)。

レベルとセグメントの対応 (実測から導出):
- 範囲は −60 から 0 dBFS を 30 セグメントに等分 = 1 セグメントあたり 2 dB。点灯数 = (値 + 60) / 2。サンプルで検証済み: −18 dBFS で 21 点灯、−22 で 19、−24 で 18、−10 で 25。
- 無音: 値の文字は「−∞ dBFS」、30 セグメントすべて meterOff、ピーク目印も無し (13 の自分側)。
- 琥珀: 03 の相手側 (−10 dBFS) でセグメント index 23 と 24 (index は 0 始まり、−14 から −10 dBFS 付近) が琥珀。琥珀の開始しきい値の定義は文書化されていない (曖昧)。
- meterRed (#f18e83) の使用例は無い。クリップ域に使う想定と推測できるが、frame には出てこない (曖昧)。
- ピーク目印の位置サンプル: 03 自分 (現在 −18) は index 23、03 相手 (現在 −10) は index 26、02 マイク (現在 −22) は index 21、07 マイク (現在 −24) は index 21、13 相手 (現在 −18) は index 23。いずれも現在値より右。ピーク値自体の数値表示は無い。

プロトタイプ値の文言 (Foundations frame、メーター直下、verbatim):
「試作の値：50ms集計 / ピーク保持800ms / 下降24dB毎秒。実測のsample peakを使い、無音では動かさない。」
読み取り: 50 ms 単位で集計、ピーク保持 800 ms、下降速度 24 dB/秒、値は実測の sample peak、無音では動かさない。
00 の範囲説明: 「メーターの動きは別の動作サンプルで確認。」(動きそのものは Figma に無い。静止画の点灯数のみ)。

配置:
- 02 録音の準備: 「自分」カード内にマイクだけ (名前「マイクの入力」)。「相手」側はメーター無し (「相手の入力確認は録音開始後に行います。」)。
- 03 録音中: 自分と相手の 2 本を縦に並べる (名前「自分  ·  USBマイク」「相手  ·  Google Chrome」)。
- 07 設定 — 録音: マイクのプレビュー (名前「マイクの入力」)。
- 13 入力停止: 同じ 2 本。自分側は無音表示。

### 1.9 ear アセット (Kikimimi / Ear asset、node 5:223)

64 x 64 の PNG (透過)。ウサギの耳を 2 つ並べた墨色の線画マーク。`ear-asset.png` に保存済み。使用: Foundations で 64、01 と 12 の toolbar で 32 x 32 (横に「Kikimimi」heading)。他の画面の toolbar では使わない。

### 1.10 共通部品の寸法まとめ

- Window toolbar: 高さ 64、背景 paper、padding 20、要素間 12、縦中央。タイトルバーと toolbar は 1 本の 64 高の帯で、信号機が帯の中に左端で同居し、ウィンドウタイトルの文字は無い (SwiftUI/AppKit では、タイトルを隠した統合ツールバー型の窓に相当する形。実装方法はこの文書の範囲外)。
- toolbar のアイコン (歯車、chevron-left) は Simple Design System ライブラリのアイコン (歯車 20 x 20、chevron 40 x 40 のインスタンス内) で、独自アセットではない。SF Symbols への置き換え可否は Figma からは判断できない (曖昧)。
- Page heading: 幅 992、横並び、間隔 16、左に Title ブロック (幅 700。title + small 補足、間隔 4)、右端に主ボタン (任意)。
- Field: ラベル (label ink) + 間隔 8 + 入力欄 (surface、1px control 枠、角丸 8、padding 12、文字 body 16/28)。
- Grouped rows (設定): 背景 paper、角丸 8、行 padding 16、行間 1px Divider。
- State (状態ドット): 7px 円 + 間隔 8 + label 文字。円と文字は同色 (success または danger)。
- Notice: 背景 {successBg | warningBg | dangerBg}、padding 16、角丸 8、縦間隔 4。見出し行 (label 14/22 Medium、状態色、右端に任意の secondary ボタン) + 説明 (small secondary)。アイコンは無い。
- ダイアログ / メニューバーカード: 背景 surface、1px line 枠、角丸 12、padding 32、縦間隔 24。スクリム・影の描画は frame 内に無い。

## 2. ナビゲーションモデル

以下は 「観察された事実」(スクリーンショット、構造、プロトタイプのクリック遷移の実値) と「曖昧」を分けて書く。

### 2.1 ウィンドウと設定の位置

観察された事実:
- メイン画面は 1120 x 840 の 1 ウィンドウ。01 から 06、12、13、14、15 と設定 07 から 11 の全てが同じ窓枠 (角丸 14、64 高の toolbar) で描かれ、画面は同じ窓の中で差し替わる。
- 設定は別ウィンドウではなく、同じ窓の中のページとして描かれている。設定ページにも同じ toolbar (戻る + 設定) が付き、プロトタイプでも同じフローの NAVIGATE で遷移する。設定ページ内は左サイドバー (幅 248) + 右コンテンツ (幅 872) の 2 カラム。
- 根拠の強さ: Figma のプロトタイプは「別ウィンドウ」を表現できないため、NAVIGATE の配線だけでは別ウィンドウでない証拠にならない。強い根拠は見た目の側にある。設定ページが本体窓と同じ 1120 x 840 の窓枠・同じ toolbar (信号機つき) を持ち、戻るボタンの文言が「設定」ではなく「録音一覧」であること。実装側が既に別構造 (例: サイドバー付きの設定分割) を持つ場合、どこまでが「描かれた形」でどこからが「必須要件」かの線引きは、この文書では判断していない。
- メニューバーのポップオーバー (16) は別の面 (380 x 409 のカード)。ここの「録音画面を開く」は 03 へ、「設定を開く」は 07 へ遷移する。

### 2.2 一覧 → 詳細の構造

観察された事実:
- 01 録音一覧 がルート (toolbar は 耳 + 「Kikimimi」、戻るボタン無し)。12 はじめての準備 も同じルート型の toolbar。
- 録音一覧の行 (行全体または「開く」) は 05 文字起こし へ進む。05 はその録音の詳細ページで、タブは「文字起こし」「要約」の 2 つ。「録音の情報」はタブ行の右端に置かれた枠なしテキストボタン (タブの 1 つではない)。
- 「新しい録音」と予定行の「録音を準備」は 02 録音の準備 へ進む。02 の「録音を開始」で 03 録音中、03 の「録音を停止」で 04 保存後・文字起こし中。04 の「録音一覧に戻る」で 01。
- つまり メインは「一覧 → ページ」のスタック型で、2 カラムの Master-Detail (一覧と詳細が同時に見える形) ではない。

### 2.3 toolbar の中身 (画面別)

| 画面 | 左 (leading) | 右 (trailing) |
| --- | --- | --- |
| 01, 12 | 信号機、耳 (32)、「Kikimimi」(heading) | 歯車 + 「設定」 |
| 02, 03, 04, 05, 06, 13, 14 | 信号機、戻る chevron (40 x 40)、「録音一覧」(テキストボタン 88 x 40) | 歯車 + 「設定」 |

### 2.5 曖昧・矛盾の指摘 (ナビゲーション)

1. 設定ページから戻る先は常に 01 だが、02 の「変更」で 07 へ行った場合も、戻ると 02 ではなく 01 になる。入力途中の 02 の状態が失われるかは不明。
2. 04 から 05 への遷移 (文字起こし完了後) はプロトタイプに無い。完了時に 04 が 05 に変わると読めるが、明示されていない。
3. 04 の「Finderで表示」の遷移先が「詳細 / 録音の情報」になっている。Finder を開く操作の遷移先として不自然 (プロトタイプの仮配線と読める)。
4. 確認 / 要約の送信 の「キャンセル」は 14 ではなく 05 に戻る。14 の「要約」タブ自体の遷移先が 06 になっている (要約が無いのに 06) 点と合わせ、14 と 06 の関係は仮配線の疑いがある。
5. 15 には設定サイドバーが無く、単一カラムのページ。10 から 15、15 から 10 の往復はあるが、15 の戻るは「録音一覧」(設定ではない)。
6. 12 はじめての準備 に至る条件 (初回起動か、許可不足時か) と、12 から 01 へ進む経路は、プロトタイプに無い。12 の全ボタンは 07 へ進む。
7. 窓のサイズ可変性、最小サイズ、992 幅の中身カラムが窓拡大時にどう配置されるかは未指定。
8. 録音中に窓を閉じたときの再表示、設定を開いたときの戻りは 03 / 16 の copy (「ウィンドウを閉じても録音は続きます。」) 以外に指定が無い。

## 6. 新機能に見える項目 (候補)

スタイルの置き換えではなく、機能や挙動の追加に見えるもの。現行アプリに既にあるかは判断していない。

1. レベルメーター (30 セグメントの dBFS 表示、ピークホールド、琥珀 / 赤の域、目盛り、「−∞ dBFS」) を、録音準備 (02)、録音中 (03、13)、設定 (07) に置く。試作値: 50ms 集計、ピーク保持 800ms、下降 24dB/秒、sample peak、無音では動かさない。
2. 録音中の入力状態表示: 自分と相手のメーターを別々に出す。「両方の音声を受信しています」の健全性表示。入力停止の警告 Notice (13)「自分の音声が途切れました」と、片側は続行中の表示「相手の音声は録音を続けています」。「今の録音では入力を再開できない」前提の copy。
3. はじめての準備 (12): 3 ステップのオンボーディング (マイク許可、画面収録の許可、使用マイク選択) と「あとから設定できること」。
4. 録音準備画面 (02) 一式: 会社名 (必須) とタイトル (任意) の入力、カレンダーの予定から開く文脈表示、相手の音声を録音するアプリの選択 (アプリ単位の音声取り込み)、許可状態の表示、「文字起こしは録音を止めた後に始まります。」。
5. カレンダー連携: 録音一覧の「これからの予定」パネルと予定ごとの「録音を準備」(01)、設定 — カレンダー (09) のアクセス状態、カレンダーごとの表示スイッチ、「すべて表示 / すべて非表示」。
6. 設定を 5 ペイン (録音 / 文字起こし / カレンダー / 要約 / 書き出し) の窓内ページにまとめる構造と、サイドバー付きレイアウト。マイクの入力チャンネル選択 (07)、「前回選んだアプリ」の記憶。
7. 録音後の流れ: 「録音を保存しました」の保存通知と文字起こし進捗のパーセント表示 (04)、「Finderで表示」で音声ファイルを確認、ほかの録音中は文字起こしを待機して再開する挙動 (08 と状態 frame)。
8. 文字起こしを読む画面 (05): 話者 (自分 / 相手) と時刻付きの本文、「文字起こし / 要約」タブ、タブ行右端の「録音の情報」。
9. 録音の情報カード: 会社名、タイトル、日時、録音時間、自分 / 相手の音声の保存状態、「文字起こしをやり直す」。
10. 要約まわり: 手動のみで要約を作成する空状態 (14)、送信前の確認ダイアログ (初回のみ読める注記つき)、「作り直す」、「要約は自動生成された内容です。必要に応じて文字起こしと照合してください。」という出所表示 (06)。
11. 要約の接続設定: 「ChatGPTでサインイン」と「APIキーを使う」の 2 方式 (10、15)、ChatGPT のアカウント / サインアウト、モデル一覧の更新、API キーのキーチェーン保存と削除、「ChatGPTの利用上限は、ほかのアプリと共有します。」「OpenAI APIの利用料金がかかります。」の注記。
12. 書き出し: Markdown コピー (05)、ノートの書き出し (確認 → 完了)、書き出し先フォルダの選択と解除 (11)、同じ録音の再書き出しで更新、書き出し後に内容が新しくなった場合の通知 (状態 frame)、音声ファイルは書き出さない旨。
13. メニューバー: 録音中の面 (16) に「録音中」、会社名、経過時間、「録音を停止」、「録音画面を開く」、「設定を開く」。03 の「ウィンドウを閉じても録音は続きます。メニューバーからも録音を止められます。」。
14. 状態の伝え方 (状態 frame): モデルのダウンロード要求、録音終了待ち、文字起こし失敗と再試行、前回の録音の復元 (中断復旧)、ノート書き出し失敗、書き出し済みノートが古い、許可反映のための再起動。
15. 戻るナビ: 子画面で toolbar 左に chevron +「録音一覧」を常設し、右に「設定」を常設する構造 (録音中も)。
16. 録音一覧の補助情報: 行ごとの状態 (「文字起こし済み」「要約あり」)、長さ、「新しい順」、件数「4件の録音」、「録音と文字起こしは、このMacに保存されます。」。
17. デザイン基盤: 変数化された色と余白のトークン、文字スタイル 7 種、focus 色 (#ffd43b) の定義、Noto Sans JP の使用。
