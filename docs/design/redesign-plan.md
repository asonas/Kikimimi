# Kikimimi 画面の作り直し計画

Figma の「Kikimimi 画面設計」ページ（fileKey `2KlVbPxcvVWwvMEmTOK4ED`）に合わせて、メインウィンドウ、録音の流れ、設定、メニューバーを作り直す。対象は Kikimimi を使う本人で、面接の前に準備を整え、録音中は声が入っていると分かり、終わったあとに落ち着いて読み返せるようにする。

3 列の常設パネル（642ce88）はやめ、録音一覧から 1 つの録音のページへ進む作りにする。設定は別ウィンドウのまま残し、中身の見た目を Figma に合わせる。暗い配色も用意する。

作業は R0 から R9 の 10 単位に分け、1 単位を 1 コミットとして main に積む。

## 読み方

1 つのチェックボックスが 1 つの作業で、確かめ方を添えてある。証拠（コミット、テストの結果、スクリーンショット、利用者の確認）が揃ったときだけチェックする。

このリポジトリは PR を使わず、main に署名付きのコミットを積む。push はしない。実装は herdr のペアコーディング（リードと Codex のコーダー）で行う。各単位で、コーダーの差分をリードが読み、テストし、アプリを起動して確かめてからコミットする。

テストだけでは確かめたことにしない。各単位は、単体テスト、実画面の確認、性能の確認がすべて済んで、はじめて完了とする。

## 決まっていること

利用者が 2026-11-11 に決めたこと。

- 設定は別ウィンドウ（⌘,）のまま。中のページの見た目を Figma の 07〜11、15 に合わせる。
- 暗い配色も作る。明るい配色は Figma の値どおりにする。暗い配色は同じ色の役割を保ってリードが決め、画面で見てもらう。
- 細かく動くメーター、はじめての準備、復元と書き出しの確認、メニューバーの録音中表示を、今回の範囲に含める。

Figma で決まっていない点は、リードが次のように決めた。違うときは利用者が言えば変える。

- 文字はシステムフォントを使う。Noto Sans JP は同梱しない。設計資料の README も同じ方針である。経過時間と dBFS には等幅数字を使う。
- 録音のページで何を表示するかは、録音の状態から決める。録音中なら 03、保存中や文字起こし中なら 04、文字起こしが済んでいれば 05 と 06 を出す。こうすれば、04 から 05 への遷移が Figma で配線されていない点も、状態が変われば画面が切り替わることで解決する。
- 確認、完了、録音の情報のカードはシートで出す。メニューバーの面は、今の MenuBarExtra のポップオーバーを使う。
- 04 の「Finderで表示」は Finder を開く。Figma の配線は仮のものと判断した。
- 録音一覧の行には、Figma の 2 種類（文字起こし済み、要約あり）に加えて、録音中、文字起こし中、失敗、要対応も文字で出す。
- ウィンドウの最小サイズは 960 x 640 とし、本文の幅は 992 を上限に中央へ寄せる。

## 前提となる事実

- Design の仕様書は `docs/design/redesign-spec.md` にある（R0 で取り込む）。24 画面の画像は `docs/design/figma/` に置く。
- 要約の処理は表示中の View が `@State` で持っていて、画面から外れると取り消される（`App/SessionSummaryView.swift:53`）。ページを行き来する作りにする前に、処理を View の外へ移す必要がある。
- 録音中のメーターは 1 秒に 1 回しか更新されない（`core/Sources/RecorderAudio/Audio.swift:231`）。無音の判定（`SilenceMonitor`）は、この 1 秒ごとの値で動いている。
- 色、文字、ボタンを共通で決めた仕組みはまだない。アセットカタログには色が入っていない。
- App のテストターゲットはない。`mise run test` は core パッケージだけを対象にする。画面の確認は `mise run app` で起動し、computer-use でスクリーンショットを撮るか、利用者に見てもらう。
- 新しい Swift ファイルは XcodeGen が拾うので、プロジェクトへの登録は要らない。

## 付録 A. 試作で確かめたこと

- メーターの計算は、`docs/design/unslop/meter.test.mjs` の 8 件で確かめてある（別の Codex セッションが作成）。Swift への移植は R5 で行う。

## 付録 B. 選ばなかった案

- 設定をメインウィンドウの中のページにする案。Figma はこの描き方だが、利用者が別ウィンドウを選んだ。録音中や録音の準備中に設定を開いても、元の画面が消えないためである。
- 3 列の画面に Figma の見た目だけを当てる案。本文の幅が狭いままで、長い文字起こしが読みにくいので選ばなかった。
- Noto Sans JP を同梱する案。設計資料の README がシステムフォントを使うと決めているので、それに従う。

## 付録 C. 危険なところ

- R2 の前に R3 を入れると、ページを離れたとき要約が止まる。順番を守る。
- R5 は音声を扱う部分に手を入れる。保存の経路と無音の判定を変えると、本物の面接の録音が壊れるおそれがある。表示用の経路は分け、録音の本番前に利用者に 1 回試してもらう。
- R4 で `Window("新しい録音")` のシーンを消すと、メニューバーから録音を始める手順が変わる。メインウィンドウが閉じているときにも準備のページへ進めることを確かめる。
- R8 の実画面の確認は、許可がない状態を作れないので、DEBUG の起動引数で代わりに確かめる。本当の初回起動は確かめられていないと記録する。
