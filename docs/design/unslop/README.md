# Kikimimi 画面再設計

2026-11-10。現状の機能は `d4a4f9c` の実装で確認。画面と操作の設計案であり、SwiftUIアプリへの反映はまだ行っていない。

## 確認する

- [Figmaの機能の地図](https://www.figma.com/design/2KlVbPxcvVWwvMEmTOK4ED/Kikimimi?node-id=15-671)
- [録音中の画面](https://www.figma.com/design/2KlVbPxcvVWwvMEmTOK4ED/Kikimimi?node-id=6-755)

- [メーターの動作サンプル](http://127.0.0.1:8765/docs/design/unslop/meter.html)

Figmaには録音一覧・準備・録音中・文字起こし中・本文・要約・初回準備・5分類の設定を作成。入力停止、コピー、書き出し確認、要約の送信確認、メニューバーなども含む。主要な操作をクリックで移動できる。値の入力、OSのダイアログ、実際の録音や文字起こしは動かない。

メーターのサンプルを起動し直す場合は、リポジトリのルートで次を実行する。

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

`meter.html` は合成したPCMから測定したメーターを表示する。実マイクは「実際のマイクで試す」を押して許可した場合のみ使用し、音声を保存・送信・再生しない。停止時にマイクへの接続を終了する。実マイク経路は今回の操作確認には含めていない。

`figma-*.js` はFigma Plugin APIでの作成用コード。Node.jsで直接実行するものではない。`figma-state.json` に保存済み画面とコンポーネントのIDを記録している。既存画面への再実行を想定した自動同期ツールではない。

## 目的

面接前に録音の準備ができ、会話中は声が入っていると分かり、終了後は自分の言葉と相手の言葉を落ち着いて読み返せること。録音一覧、録音の準備、録音中、振り返りを作業単位とする。設定は別ウィンドウにまとめる。

## 設計で変える点

- 3列の常設パネルをやめ、一覧と文書の詳細を行き来する。本文には十分な横幅を使い、長文を読みやすくする。
- 表記を「文字起こし」に統一する。話者は色で分類せず「自分」「相手」と時刻で示す。
- 状態表示は目的に合わせる。録音中には音源、保存後には音声の保存と文字起こし、要約には送信先と操作結果を示す。
- 設定は「録音」「文字起こし」「カレンダー」「要約」「書き出し」。見出し、説明、現在値、操作を行単位にまとめる。
- UID、内部モデル識別子、デバッグ用情報は普段の操作面から外す。必要な診断情報は詳細表示へ。
- 録音の準備で自分の入力を確認できる導線、書き出し内容の事前確認、読みやすい入力障害の説明を追加する。これらは設計提案で、実装済み機能とは区別する。
- 一時停止、アプリ内音声再生、リアルタイム文字起こし、全文検索は現状にないため、この案の操作には追加しない。

## 見た目とアクセシビリティ

採用済み耳アイコンの生成り `#f5f5f4` と墨色 `#1c1917` を基調とする。本文は白、補助文は `#57534e`。色は録音・注意・入力レベルなど意味のある箇所に限定する。RandomA11yの `#f8fafc` / `#0f172a` は比較用の寒色案として記録し、今回はアイコンとの連続性を優先する。

FigmaはNoto Sans JPに統一する（SF Proは接続先のレンダラーで数字が表示されなかったため）。実装ではmacOSのシステムフォントを使う。本文16pt、行間28pt、補助13〜14pt、主な操作領域40pt以上を基準とする。キーボードフォーカスは黄と黒の二重表示、状態は色と文字を併用。長文の行長を抑え、文字拡大時は並列の項目を縦に積む。Figmaの静止画確認だけでVoiceOver対応や規格適合を保証しない。

配色の計算値は、本文と白が17.49:1、補助文と生成りが6.99:1、操作部の境界と白が4.80:1。成功・注意・エラーの文字とそれぞれの背景はいずれも6:1以上。境界色 `#d6d3d1` は装飾的な区切り線に使い、操作部の識別には濃い `#78716c` を使う。

## 音声メーター

現状は `core/Sources/RecorderAudio/Audio.swift` のTrackRecorderが音声1秒分の最大値をまとめ、`RecordingController.levels` 経由で `App/SessionPresentation.swift` のProgressViewに渡す。設定画面のマイクプレビューは別経路で各PCMチャンクのピークを受け取る。録音とプレビューで更新の粒度が異なる。

新しいメーターは自分・相手の2本。Ladiocastの横長バーと明瞭な音源との対応を参考にし、-60〜0 dBFSの目盛り、短時間ピーク、ピーク保持線、無音／入力停止の文章を加える。L/Rの表示はしない。現在の保存トラックは各音源をモノラル化しているため。

以下は試作の初期値で、Ladiocastの内部実装を測定した値ではない。

- PCMから50ms窓のsample peakを集計（20Hz）。録音保存と無音監視から表示用の経路を分離する。
- 上昇は次の描画で反映。下降は24dB/秒。ピーク線は800ms保持後に下降。表示のために音声を加工しない。
- 目盛りは-60、-48、-36、-24、-12、0。-12以上は黄、-3以上は赤。0dBFS到達は「音割れの可能性」。これはsample peakでありtrue peakやLUFSではない。
- 描画は画面更新に同期。数値もバーと同じ表示モデルから同じタイミングで更新し、整数値が変わったときだけ描き直す。無音時に架空のバーを動かさない。
- 無音と入力停止を区別する。未測定は「—」、フロア以下は「−∞」、入力が失われた場合は「入力停止」。古い値を表示し続けない。
- 録音停止後はメーターを終了し、文字起こしの進捗を表示する。動きを減らす設定では滑らかな下降を省き、測定窓ごとの値を描く。
- VoiceOverでは音源と状態を読み上げ、毎フレームの数値は通知しない。状態変化のみ通知する。
